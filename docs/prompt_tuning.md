# Prompt 调优迭代记录

> 日期：2026/08/13
> 目标：优化"追问机制"的 Prompt，让 AI 追问更有针对性
> 更新（2026-09-01）：追踪 Prompt 已迁至 `prompts.py` 单源（决策树 A-E / 三条铁律 / 6 档评分锚点），

> 本轮迭代记录的"最终版"为历史版本，可对照 `prompts.py` 查看当前生效版本。

---

## 迭代对象

`/interview/chat` 接口中的追问 Prompt（决定 AI 面试官的追问质量）

---

## 第 1 轮：基础版（不给判断逻辑）

**Prompt**：
```
你是面试官。候选人刚回答了你的问题，请追问。
候选人回答：{answer}
```

**观察**：
- 追问很泛，像在问一个新问题
- 不扣候选人回答里的关键词
- 感觉 AI 没有"听"候选人说了什么

**问题**：没有告诉 AI 该怎么判断——是追问细节还是推进下一题？

---

## 第 2 轮：加判断逻辑 + 上下文

**Prompt**：
```
你是面试官。候选人刚回答了你的问题，请追问。

【岗位 JD】{jd_text}
【候选人简历】{resume_text}
【面试历史】{history}
【候选人本轮回答】{answer}

追问要求：
1. 如果回答有漏洞就追问细节
2. 如果回答完整就推进到下一个相关问题
```

**观察**：
- 追问开始有方向了，会参考简历和 JD
- 但追问还是偏长，有时候会寒暄
- 偶尔会问一个跟回答无关的新话题

**进步**：有了判断逻辑 + 上下文，追问质量明显提升
**不足**：输出不稳定，长度和风格不一致

---

## 第 3 轮：限制长度 + 历史截断 + 不要寒暄（最终版）

**Prompt**：
```
你是面试官。候选人刚回答了你的问题，请根据他的回答追问。

【岗位 JD】{jd_text[:500]}
【候选人简历】{resume_text[:1200]}
【面试历史（最近几轮）】{history[-6:]}
【候选人本轮回答】{answer}

追问要求：
1. 如果回答里有技术漏洞、含糊、没展开的细节 → 追着这个点问，问细节
2. 如果回答很完整 → 推进到下一个相关问题（基于简历/JD）
3. 问题要具体、有追问感，体现你真的听了他刚才说的话
4. 只输出追问内容，不超过 80 字，不要寒暄
```

**关键改动**：
| 改动 | 原因 |
|------|------|
| `history[-6:]` 只取最近 6 条 | 控制 token 费用，避免历史太长 AI 抓不住重点 |
| `resume_text[:1200]` 截断 | 简历太长会稀释关键信息 |
| `不超过 80 字` | 强制简洁，追问就该短平快 |
| `不要寒暄` | 干掉"很好的回答！不过我想再追问一下"这种废话 |
| `体现你真的听了` | 让 AI 必须引用候选人回答里的关键词 |

**实测效果**：
> 候选人："核心难点是流式输出和多轮追问的状态管理"
> AI 追问："你提到'流式输出和状态管理是核心难点'，能具体说说：流式响应时如何保证 SSE 连接不中断？多轮对话状态存在 SQLite 哪张表？"

✅ 扣住了"流式输出""状态管理"，追问具体有细节

## 评分报告 Prompt（结束面试用）

最终版 Prompt 要求 AI 输出结构化 JSON：

```json
{
  "score": {
    "technical": 72,
    "communication": 80,
    "logic": 75
  },
  "strengths": ["优点1", "优点2", "优点3"],
  "improvements": ["不足1", "不足2"],
  "overall_comment": "综合评语（3句话）"
}
```

**设计思路**：
- 三个维度打分（技术深度、表达能力、逻辑性）→ 面试官一眼看完
- 0-100 整数 → 前端可以做雷达图/柱状图可视化
- strengths + improvements 分开 → 候选人知道哪里好、哪里要改

---

## 总结：Prompt 调优的核心方法

| 步骤 | 做法 |
|------|------|
| 1. 基线 | 先用最简单的 Prompt，看 AI 默认表现 |
| 2. 加约束 | 加判断逻辑、格式要求、长度限制 |
| 3. 控上下文 | 截断过长内容，只给关键信息 |
| 4. 实测对比 | 每改一处，跑同样的输入看输出变化 |
| 5. 记录 | 把每轮改动和效果记下来（就是这篇文档） |

> 这个迭代过程本身就是 Prompt 调优方法论的完整演示：从基线到约束、再到上下文控制的完整链路。
